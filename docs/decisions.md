## 2026-11-14 API 인스턴스 (`src/shared/api/`)

- axios 인스턴스(`http`)를 씀 — 팀이 axios가 편하고 타임아웃(10초)·업로드 진행률 같은 기능이 필요해질 수 있음. 처음엔 `fetch`로 만들었다가 교체, 호출부 `api.get<T>()`는 그대로
- 성공하면 응답의 `data`를 꺼내 돌려주고 실패는 `ApiError`(status·code·fieldErrors)로 던짐 — 공통 규칙의 응답 형식, 분기는 문구가 아니라 code
- Access Token은 모듈 메모리에만 — 확정 정책(localStorage 금지), Refresh Token은 쿠키라 `withCredentials: true`
- 재발급은 `AUTH_ACCESS_TOKEN_EXPIRED`일 때만, 동시 요청이 몰려도 한 번만 실행하고 원 요청은 한 번만 재시도 — 같은 Refresh Token을 두 번 쓰면 REUSED로 세션이 끊김
- 재발급까지 실패하면 `setAuthLostHandler`로 앱에 알림 — 로그인 화면 이동은 `app/`이 연결(여기서는 모름)
- `restoreSession()`은 앱 시작 때 한 번 호출 — 새로고침하면 메모리 토큰이 사라지는데 서버는 "토큰 없음"을 EXPIRED가 아닌 INVALID로 줌
- `Idempotency-Key`는 옵션으로만 지원 — 명세가 제안 단계라 적용할 API(고민 작성·돌봄 완료/취소·휴식 시작)가 호출할 때 켬
- 기능별 요청 함수(`xxxApi.ts`)와 mock 제거는 안 함 — 이번에는 인스턴스만, mock은 그대로(2026-11-15 `shared/mock`으로 통합)

## 2026-11-15 TanStack Query

- `@tanstack/react-query` 도입 — 감정 목록을 양 먹이주기 화면에서 미리 받아 캐시하고(작성 화면 칩이 바로 보임), 저장 후 기록 목록을 바로 갱신하려고. devtools 등 다른 패키지는 안 넣음
- `QueryClient`는 `app/queryClient.ts`, Provider는 `main.tsx` — 앱에 한 번만 설정하는 것(CLAUDE.md `app/` 역할). 기본값은 `retry: 1`·창 포커스 재조회 끔만 바꿈
- 쿼리 키·옵션은 `features/emotion/emotionQueries.ts`에 한곳, `index.ts`로 공개 — 기능 안에 두고 규칙 3을 지킴
- 감정 목록은 `staleTime` 1일·`gcTime` 7일 — 거의 안 바뀜. 기록 목록은 기본값(저장 때 invalidate)
- 미리 받기는 `usePrefetchEmotions()`를 EmotionPage가 호출 — 칩 캐시가 없을 때(작성 화면 직행)만 칩 스켈레톤·"다시 시도" 표시
- 저장 성공 시 기록 목록 캐시에 새 기록을 먼저 끼워 넣고 invalidate — 목록 화면이 닫혀 있어서 invalidate만으로는 옛 목록이 잠깐 보임
- `useEmotionRecords`·`useCreateEmotionRecord`도 TanStack Query로 통일, 반환하는 상태 모양(loading/error/success, already-exists)은 그대로 — 페이지 변경 최소화
- 홈 요약도 TanStack Query로 캐시(2026-11-15 변경, `features/home/homeQueries.ts`) — 다른 탭에 다녀올 때마다 이름·양털 자리에 스켈레톤이 다시 뜨던 문제. 캐시된 값을 바로 보여주고 들어올 때마다 뒤에서 새로 받음(감정 기록·양털이 다른 화면에서 바뀌므로 staleTime 0)

## 2026-11-19 앱 다시 열 때 지난 값 먼저 (`feature/query-persist-idb`)

- 서버 데이터 캐시(TanStack Query)를 IndexedDB에 저장(`@tanstack/react-query-persist-client` + `query-async-storage-persister` + `idb-keyval`, 쓰기 1초 throttle) — iPhone PWA가 자주 종료돼 다시 열 때마다 스켈레톤부터 보이던 것. 번들 +2.4 KB(gzip)
- 저장 대상(허용 목록): 홈 요약·양털 잔액·내 정보·감정 종류·감정 기록 목록·돌봄 행동·오늘 돌봄 완료·내 고민 목록·보관한 치즈 목록. 실패한 쿼리·mutation은 저장 안 함
- 저장 안 함: 고민 상세 본문·받은 위로·감정 기록 한 건(개인적인 글 최소화 — 목록에 이미 있는 미리보기로 충분), 위로할 남의 고민 목록(진입마다 새로 받는 규칙), 휴식 상태(시간에 따라 바로 바뀜), 약관 내역·양털 내역(자주 안 봄), 섬 꾸미기(아직 mock)
- 저장본 주인 = Access Token JWT `sub`(백엔드 `AccessTokens`가 회원 id) — `/users/me`를 기다리지 않고 토큰 재발급 직후 확인. 주인이 다르면 바로 지움, 세션 복원 전에는 캐시에 넣지 않음
- 되살린 내 정보가 초기 설정·온보딩 완료면 `/users/me`를 기다리지 않고 바로 앱을 열고 뒤에서 확인 — 두 값은 true에서 false로 안 돌아감. 첫 표시 6.2초 → 2.3초(API 2초 지연 기준)
- 로그아웃·계정 바꾸기·로그인 풀림·비밀번호 재설정·앱을 열 때 재발급 거절(4xx)에서 저장본 지움. 재발급이 네트워크 오류·5xx로 실패하면 남김(주인 확인이 있어 다른 계정에 안 보임)
- 오늘 데이터(홈 요약 `today`, 오늘 돌봄 `actionDate`)는 서울 날짜가 바뀌었으면 되살리지 않음 — 어제 완료가 오늘 완료로 보이지 않게. 감정 기록 목록은 기록마다 날짜가 있어 그대로
- 되살린 값은 모두 오래된 것으로 표시해 화면에 붙자마자 다시 받음(같은 자리에서 값만 바뀜). 저장 대상 gcTime = maxAge
- IndexedDB를 못 쓰면(없음·열기 실패·저장 거부) 조용히 지금처럼 동작. 1초 안에 못 읽으면 기다리지 않음
